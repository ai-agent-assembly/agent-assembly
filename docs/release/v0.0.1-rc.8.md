## v0.0.1-rc.8 — Agent Execution Runtime 2.0 foundation, first-run fixes, and a security-fix batch

Eighth release candidate in the v0.0.1 series (patch on the `rc` channel,
`rc.7 → rc.8`). The window centres on the first cut of **Agent Execution Runtime 2.0**
(Epic AAASM-6159) for `aasm run`, plus first-run/CLI fixes, MCP and egress hardening, and
dependency-advisory remediation. Full detail in [`CHANGELOG.md`](../../CHANGELOG.md).

> **Not for production use.** At `0.x.y` SemVer, rc carries no API/ABI/wire-protocol
> stability commitment. `protocol/v1` is unchanged.

> **Runtime 2.0 in rc.8 is a foundation, not a finished guarantee.** Several pieces are
> opt-in, partial, or not independently qualified. Read **Known limitations** below
> before relying on any of them.

### Breaking and behaviour changes

- **BREAKING: the `aasm` CLI's default API URL is now `http://localhost:7391`** (was
  `http://localhost:8080`) (AAASM-6385). `aasm start` records its bound address in
  `~/.aasm/gateway.url`. To keep targeting 8080 pass `--api-url http://localhost:8080` or
  save a context (`aasm context set local --api-url http://localhost:8080`).
- **`aasm run --root-agent X` now refuses at plan time** (`AncestryUnresolved`), with or
  without a lease, because no mechanism yet trust-resolves a declared parent (AAASM-6277,
  AAASM-6273). It previously ran silently as a root launch.
- **All-or-nothing lease rule is live (Core ADR 0038):** once a policy authors any
  `authority.leases` grant, every domain the launch requires needs its own covering lease.
  `aasm run` prints a non-fatal diagnostic naming uncovered domains.
- **Local state is owner-only (AAASM-6387):** `~/.aasm`, `~/.aa` and the default audit
  directory are created `0700`, databases/JSONL `0600`. An *existing* default location left
  loose by an older version is tightened when you own it and it is not a symlink. Group-shared
  deployments must keep data elsewhere (`AA_GATEWAY_DB_PATH`, `AA_AUDIT_DIR`, configured
  storage path).
- **Lease-governed runtimes deny `LLM_CALL` / `TOOL_RESULT` policy queries** (AAASM-6259,
  `AA_LEASE_POLICY` set); only `TOOL_CALL` is admitted. No shipped SDK sends the other two.
- **Policy validation is stricter:** documents with no enforcement section, blank documents,
  empty sections, sections written beside `spec`, and non-finite budget limits are refused
  (AAASM-6336, AAASM-6338, AAASM-6343).
- **`aasm run --max-*` combined with an authored lease refuses the launch** (with a confining
  `--isolation` intent; `--isolation none` is not subject to that early refusal).
  `--isolation none` is refused when the effective policy requires brokered egress
  (`egress: posture: broker_required`).

### Agent Execution Runtime 2.0 (Epic AAASM-6159; ADRs 0038, 0040, 0041)

- **Capability leases (Core ADR 0038):** versioned `CapabilityLease` schema, `authority.leases`
  policy node lowered into subject-bound leases, `authority_gate` wired into
  `aasm run`'s boundary resolution, in-library monotonic attenuation across ancestry
  (transitive revocation, ledger-bound issuance), and `aasm lease init|revoke|status`.
  Attenuation is per-process; see **Known limitations**.
  Admission control for governed runs, **opt-in** via `AA_LEASE_POLICY`; not confinement.
  `aasm run --dry-run` prints a runtime-parity lease plan; `tools.<name>.capabilities`
  declarations are validated and hashed into the policy digest.
- **Credential broker and revocation:** a credential-brokerage contract and gate;
  `credentials: broker_required` lowers into the launch contract; provider keys are withheld
  from the child (confined and unconfined paths) and delivered to the proxy over a bounded
  stdin pipe; durable revocation records, a revoke-only proxy control socket, and
  `aasm proxy revoke-credential`. A brokered launch that cannot be revoked fails closed. `revoke-credential --agent` does not verify who answers the per-launch control socket, so under `--isolation none` revocation is best-effort against a hostile same-user agent (AAASM-6398).
- **Egress broker:** identity-bound, policy-governed egress contract and `egress` policy
  node, gated after `authority_gate`; default-deny and the cloud-metadata range are enforced.
  Fixes: numeric IPv4 encodings classified as restricted, IPv4-literal bypass closed,
  bracketed/backslash/IPv6 host parsing corrected (AAASM-6304, 6313, 6365).
- **Transactional workspaces (Core ADR 0040):** `aa-workspace-tx` copy-on-write staging and
  `aasm run --workspace-tx` (staged commit/discard, `--workspace-tx-protect`,
  `--workspace-tx-approve`, `--workspace-tx-exclude`, plan shown in `--dry-run`).
  A leftover apply journal makes the next `--workspace-tx` over the same base refuse, and a
  failed apply reports `apply_interrupted` (AAASM-6305).
- **Resource ceilings (Core ADR 0041):** `--max-*` flags on `aasm run`, each lowered as its own
  requirement; memory/PIDs lower on the sandlock backend and open-files/file-size
  (`RLIMIT_NOFILE`/`RLIMIT_FSIZE`) on the native backend. Wall-clock and CPU-seconds are
  observe-only signals in the ADR, not prevention mechanisms.
- **Execution receipts:** versioned, content-digest-sealed receipt written at the end of a
  confined run (`aasm run`'s confined path); `aasm receipt list|inspect|verify`.
- **Backend planner:** `aasm run --isolation auto` selects a backend through the isolation
  planner's candidate evaluation.
- **Host-capability broker:** `aasm host` front door (`xcode list|build`, `simulator list`)
  gated on the host-capability contract.
- **Landlock native backend:** the optional v5 `ioctl(2)` right is adopted behind a measured
  ABI check (AAASM-6173). A Firecracker backend evaluation spike is written up under
  `docs/src/research/` (no backend shipped from it).
- **Coding-agent integrations:** `aa-devtool-codex` verifies the effective Codex boundary
  for an AASM-managed launch; `aa-devtool-copilot` adds a receipt-backed GitHub Copilot
  (VS Code agent mode) lifecycle integration owning one VS Code setting.

### First-run and CLI fixes

- `aasm start` detaches the daemon's stdio (so `aasm start | head` returns), logs to an
  owner-only `~/.aasm/aa-api-server.log`, detects a daemon that exits at startup, reports the
  launched server's version and path, refuses an address already in use, and names a missing
  binary with the `cargo build` command (AAASM-6385, 6389).
- `aasm status` names the URL it tried; `aasm lease init` prints the governed-runtime start
  recipe; `aasm policy validate` warns when a valid policy would be denied by a governed
  lease runtime (AAASM-6386); runtime singleton and ungoverned-health fixes (AAASM-6383, 6384).
- Documentation: source-build steps, admin-key recovery, owner-only state, first-run pointers.

### Security and hardening fixes

- **MCP enforcement in `aa-proxy`:** every JSON-RPC MCP exchange and response is evaluated
  (not only `tools/call`), event streams are judged event by event, `Content-Encoding` is
  decoded before evaluation, gateway `Redact` that the proxy cannot apply fails closed, and
  request-side gateway evaluation is bounded (AAASM-6353, 6355, 6356, 6364, 6362).
- **Gateway** judges the network stage and anomaly connections on the URL's real host and
  reports only the host in the PII-exfiltration anomaly event (AAASM-6366).
- **Per-launch proxy CA directory** is created owner-only; revocation records and control
  sockets are refused in directories others can change.
- **Dependency advisories remediated:** RUSTSEC-2026-0414 (pulldown-cmark), zstd chain,
  tokio, rustls/wasmtime, a yanked zip, `serde_yaml` replacement, `source-map-js`, and
  several lockfile advisories. Substantial Dependabot volume (Rust, dashboard, examples,
  GitHub Actions) is not itemized.

### Known limitations

Runtime 2.0 in rc.8 is a foundation. The items below describe current behaviour; they are
stated so that nothing is read as a guarantee.

- **J82 attenuation is per-process only.**
  Monotonic attenuation is enforced in-library (including 3+ generations and transitive
  revocation), not across processes: the authority witness is not serializable and there is
  no IPC for it. A launch that declares `--root-agent` is refused at plan time
  (`AncestryUnresolved`, fail closed). A launch that omits it runs as a root with only what its
  own policy and leases grant, with no comparison against the process that launched it
  (AAASM-6273). Cross-process handoff is gated behind the Core ADR 0038 Linux kernel evidence
  gate (B3), which has not been produced.
- **J83 egress attribution.**
  Each governed launch's proxy audit records carry the real agent id, but the proxy's
  `CheckAction` requests to the gateway use the synthetic id `aa-proxy` with no credential
  token. With a cascade-scoped gateway only Global-tier network policy is evaluated for proxy
  requests (Org/Team/Agent-scoped network rules are not consulted; single-file
  `AA_POLICY_PATH` deployments are unaffected), and a gateway `SecretAlert` for a response is
  attributed to `aa-proxy`, not to the agent (AAASM-6363). Destination allow/deny under the
  launch contract is separate and unchanged.
- **J85 workspace transactions.**
  Approval is a launch-time pre-authorization: `--workspace-tx-approve` accepts changes to the
  named `--workspace-tx-protect` paths without reviewing a diff, and commit then happens on
  exit 0; it is not bound to a reviewed diff (AAASM-6406). With no flag, protected-path
  changes are refused and the base is untouched. There is no `aasm workspace tx`
  show/commit/discard/recovery command. The crash fix is fail-closed, not recovery: a
  leftover apply journal makes the next run over the same base refuse and the operator
  resolves it by hand; there is no rollback (AAASM-6305). A commit is refused, with the base untouched, when any changed path sits behind a symlinked directory in the base (AAASM-6412). A commit keeps file modes: a modified file keeps the base file's mode (a `0600` file stays `0600`, an executable stays executable), an added file takes its staged permission bits without setuid/setgid/sticky (AAASM-6418). A commit that adds `A.txt` and deletes `a.txt` (a case-only rename) is refused as `boundary_escape` with the base untouched, because on a case-insensitive volume it would delete the renamed file (AAASM-6418). `--workspace-tx-protect` selectors are matched literally by path component: write a plain base-relative path (for example `src/secrets`); selectors with `./`, `..`, doubled, leading or trailing `/`, globs, backslashes or surrounding whitespace are refused at launch, as is a selector that reaches an existing entry only through case folding (write the on-disk spelling). The commit gate compares case-folded, so a case variant of a protected name is protected too. Remaining limit: Unicode normalization (NFC/NFD) variants of a protected name that does not exist yet are not folded, so such a variant created later is not recognised.
- **Resource ceilings differ per backend.** Memory/PIDs lower on sandlock; open-files and
  file-size on the native backend; both Linux. Wall-clock and CPU-seconds are observe-only
  signals in Core ADR 0041. Disk and network throughput have no ceiling flag.
- **Leases are admission control and opt-in** (`AA_LEASE_POLICY`), not confinement.
- **Execution receipts are content-digest sealed** (tamper-evident since write), not signed,
  carry an asserted (not verified) agent identity, and are written only on the confined-run
  path.
- **Host-capability broker scope:** `aasm host xcode list|build` and `simulator list` only.
  `aasm run` requests no host operation of its own (its host-capability contract is
  `not_required`).
- **Landlock native backend:** the optional v5 `ioctl(2)` right is requested where the
  measured ABI allows; network and IPC scoping are not adopted. Not qualified on a real
  kernel in this release.
- **Forensics:** `aasm receipt list|inspect|verify`; controlled replay is not implemented.
- **Host/platform support:** the macOS VM backend remains Experimental (guest kernel/rootfs
  operator-supplied, no CI lane).
