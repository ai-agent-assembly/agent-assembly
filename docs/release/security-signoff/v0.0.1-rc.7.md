## Scope note (why this is not a full rc.6..HEAD diff scan)

The `v0.0.1-rc.6..9c17c594a` delta is 2,444 files / +353,288/-17,697 —
overwhelmingly the AAASM-5819 QA-governance infrastructure itself
(`.claude/skills`, `qa/`, `scripts/qa/`, docs) plus its own prior QA dogfood
run, not shipped `aa-*` product code. Per this session's own token-efficiency
mandate ("do not duplicate a full unchanged-code audit without risk
justification"), this review is scoped to:

1. The dependency/advisory audit (whole workspace, patch-tier requirement,
   unconditional).
2. A manual security read of the actual new shipped-code delta since the
   prior QA dogfood's own tested SHA — 5 commits, 4 real files — because that
   is the only product code genuinely unreviewed by any prior gate run.

A full native `/security-review` line-by-line pass across the entire
2,444-file rc.6..rc.7 range was **not** performed this session (invoking it
literally would diff the whole range, not just the intended target — see
below); this is a recorded scope gap, not a silent PASS over unscanned code.

**Note (2026-08-23, cross-referenced from the QA sign-off):** the QA gate's
re-verification confirmed a High-severity **functional** defect,
[AAASM-5835](https://lightning-dust-mite.atlassian.net/browse/AAASM-5835) —
`python-sdk`'s `sdk-only`/LangChain governed-tool-call path fails with a
gateway identity error on every call. Assessed here for security relevance:
the failure mode is **fail-closed** (`ToolExecutionBlockedError` raised,
`raise_error=True` propagates it, the tool never runs) — it blocks the
ALLOWed action too, which is a functional break, but it does **not** let a
DENIEd action through. No fail-open / policy-bypass characteristic observed.
Tracked as a QA-owned functional defect, not a security finding; not folded
into this sign-off's verdict.
