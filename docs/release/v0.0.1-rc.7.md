## v0.0.1-rc.7 — execution isolation, trusted proxy chaining, and a security-fix batch

Seventh release candidate in the v0.0.1 series (patch on the `rc` channel,
`rc.6 → rc.7`). The largest cut since rc.6, spanning four programmes: a new
execution-isolation layer for `aasm run`, trusted upstream proxy chaining,
sensitive-data analytics/audit correlation, and a batch of gateway/proxy/CLI
security fixes. Full detail in [`CHANGELOG.md`](../../CHANGELOG.md).

> **Not for production use.** At `0.x.y` SemVer, rc carries no API/ABI/wire-protocol
> stability commitment. `protocol/v1` is unchanged.

### Execution isolation programme (`aa-isolation*`)

A backend-neutral execution-isolation layer for `aasm run`: the CLI can now
confine a governed launch's descendant processes, not only intercept their
network calls. Three backends are compiled in, each reached only when the host
actually supports it — Linux `sandlock` (Landlock-based), an AASM-native Linux
backend (seccomp + `/proc` scoping), and an **Experimental** macOS VM backend
(`Virtualization.framework`, virtiofs + vsock; operator-supplied guest
kernel/rootfs that are not shipped, no CI lane). `aasm run --isolation` gains a capability-aware `auto` mode
and reports *requested versus achieved* isolation. Security-relevant fixes
within this programme: credential exposure refused in confinement argv, and
cwd-relative `$PATH` entries rejected in launcher lookups.

### Trusted upstream proxy chaining (Core ADR 036)

`aa-proxy` can now chain through a declared, trusted upstream proxy endpoint
instead of requiring direct egress. Each `aasm run` launch gets its own
dedicated proxy instance; provider-aware credential auth-header injection lets
the proxy authenticate to a chained upstream without the agent process holding
that credential. Covered by a full negative-control test matrix and a Release
Assurance golden journey. Security fixes: CA cert/key persistence made atomic
and lock-safe, `serverAuth` EKU set on minted MitM leaf certs, and ambient
proxy-routing env sanitized.

### Sensitive-data analytics and audit correlation

Sensitive-data analytics/drill-down endpoints and dashboard views; dashboard
secret alerts now correlate to the specific proxy-side redaction event that
produced them; SDK-audit records carry a `decision_id` tying them back to the
exact policy decision; audit backpressure loss is now distinguished from
tampering. A SQLite-backed `ApprovalQueue` persists pending approvals instead
of holding them only in memory.

### Gateway, proxy and CLI security fixes

- **`aa-runtime`/`aa-cli`/`aa-api`/`aa-gateway` refuse unauthenticated
  non-loopback binds** (metrics, CLI/API, local-mode) — `aa-cli`/`aa-api` gain
  an explicit `--host` override.
- **`aa-gateway` stops logging the full webhook URL at `INFO`** on every
  startup.
- **Agent-registry tenant scoping made a type-level property.**
- **Policy hot-reload gains an operator-observable confirmation** — a policy
  file edit now logs the reloaded policy's name and version; previously the
  swap was completely silent.
- **`CheckAction` returns `Pending` immediately** instead of blocking for the
  full approval hold.
- **Retention-policy semantics reconciled** across `aa-gateway`, `aa-core` and
  `aa-api`.
- **`aa-gateway` fails boot loudly on a stale sensitive-data table shape**
  instead of starting in a degraded, unstated state.
- **Team/org scoping fixes on the topology API** — `get_team`, `cross_team`
  and `build_policy_chain` no longer treat a blank team id as a real team or
  ignore an explicit `org_id` filter.
