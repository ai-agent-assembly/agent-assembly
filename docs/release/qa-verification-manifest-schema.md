# QA verification manifest — schema

> Per-run manifest produced **once** by `/release-qa-gate`'s coordinator
> (AAASM-5821) and reused by every QA worker (AAASM-5826) so repo/Jira/branch
> discovery is not repeated per worker. Generated by
> [`scripts/qa/build-verification-manifest.sh`](../../scripts/qa/build-verification-manifest.sh)
> into `.qa/verification-manifest.json` (git-ignored — a per-run artifact, not
> a committed record; the committed record is the
> [QA sign-off](qa-signoff/TEMPLATE.md)). Consumed by the risk mapper
> (AAASM-5829) to select verification depth per
> [the release QA policy](../src/qa/release-qa-policy.md).

## Design constraints (from AAASM-5825)

- Discovery is dynamic — no hard-coded `master`, no hard-coded repo list.
- Compact metadata only — no embedded diffs, no raw logs.
- A stale local checkout is never the tested baseline; the canonical remote
  default branch is authoritative.
- CI green is one evidence field, not a QA verdict.
- Unknown/missing baseline increases verification depth; it is never silently
  treated as "unchanged."

## Schema (JSON)

```jsonc
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "manifest_version": "1",
  "generated_at_ref": "<git describe or sha of the state this manifest describes>",
  "repos": [
    {
      "repo": "ai-agent-assembly/agent-assembly",
      "default_branch": "main",          // resolved dynamically, never hard-coded
      "head_sha": "<40-char sha>",
      "baseline": {
        "source": "qa-signoff | deep-sweep-epic | released-tag | unknown",
        "sha": "<40-char sha, or null if source == unknown>",
        "reference": "docs/release/qa-signoff/v0.0.1-rc.6.md"  // or Jira key / tag
      },
      "delta_summary": {
        "commit_count": 0,
        "files_changed": 0,
        "insertions": 0,
        "deletions": 0
      },
      "affected_surfaces": ["aa-gateway/src/policy", "docs/src/qa"],
      "ci_state": {
        "checked": true,
        "conclusion": "success | failure | mixed | unknown",
        "run_url": "<gh actions run URL or null>"
      },
      "risk_tier": "LOW | MEDIUM | HIGH",     // initial pre-mapper estimate
      "excluded": false,
      "exclusion_reason": null           // required (non-null) when excluded == true
    }
  ],
  "escalations": []                       // AAASM-5820 ambiguity-escalation hatch entries, if any
}
```

## Field notes

- **`baseline.source` precedence** (first that resolves wins):
  1. latest committed QA sign-off for the applicable release lineage with
     `Verdict: PASS` (`docs/release/qa-signoff/v*.md`, matched to the current
     release series);
  2. latest completed release-verification/deep-sweep Epic with exact SHAs
     recorded (AAASM-3198/4522/4651/4690 lineage);
  3. latest trusted released tag/sign-off, where applicable;
  4. otherwise `"unknown"` with `baseline.sha: null` — the risk mapper must
     treat this as "verify broadly," not "assume unchanged."
- **`affected_surfaces`** are path prefixes, not individual files — kept small
  enough to pass to workers cheaply. The full file list is not embedded; a
  worker that needs it can `git diff --stat` itself against the recorded SHAs.
- **`excluded` / `exclusion_reason`** — a repo/surface that could not be
  verified (no access, out of scope for this release) is recorded explicitly,
  never silently dropped from the manifest.
- **`ci_state.conclusion`** is informational: it lets the coordinator skip
  re-running an already-green full suite, but a green CI never substitutes for
  QA lane verification — see the release QA policy.

## Generation

```bash
scripts/qa/build-verification-manifest.sh [<repo-path> ...]
# writes .qa/verification-manifest.json
```

Defaults to the current repo if no path is given. See the script's header
comment for exact discovery logic. `.qa/` is git-ignored — see the repo
`.gitignore` entry added alongside this schema.
