# Scenario names the `isolation-backend-native-linux` lane is expected to record
# with `"outcome": "measured"` — AAASM-5802, applying the pattern AAASM-5712
# established for the sibling `isolation-backend-linux` lane.
#
# Why a list rather than a floor. A `measured -ge N` threshold goes stale the
# moment the suite changes size, and stays green while scenarios are deleted —
# the vacuity that pattern exists to refuse.
#
# Why a list rather than a count. The ledger writes one file per scenario NAME,
# so a duplicated name collapses into a single record: "22 records" is equally
# consistent with 22 distinct scenarios and with 21 plus a duplicate. The lane
# diffs the SET of names, and takes its count from this file rather than from a
# number typed into the workflow.
#
# Why a separate file. Deriving the expected list from the test sources would
# delete both sides of the comparison at once and assert nothing. This file is a
# second artifact: removing or renaming a scenario reddens the lane until
# someone records here that the change was intended.
#
# Why a separate file from `.ci/isolation-lane-scenarios.txt`. That one is the
# Sandlock lane's denominator and the two lanes run different suites on
# different jobs. One shared file would make each lane's diff fail on the other
# lane's scenarios.
#
# `#` comments and blank lines are stripped, and order does not matter — the
# lane sorts both sides with `LC_ALL=C sort -u` before diffing.
#
