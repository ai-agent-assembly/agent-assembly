# Third-party notices

This file records **third-party software that Agent Assembly redistributes as
prebuilt bytes** inside a release artifact — binaries, object files or data
blobs that are copied into a tarball, a container image or an installed tree.

It is **not legal advice.** Each entry states the license identifier and the
obligations as written in that license's own text; it does not draw legal
conclusions about any particular distribution.

## What this file covers, and what it deliberately does not

| Class of dependency | Covered here? | Covered by |
|---|---|---|
| Rust crates in the cargo dependency graph | **No** | [`deny.toml`](deny.toml) — `cargo deny check --all-features` in the `Dependency checks` CI job. Licenses are allowlisted with implicit deny. |
| Execution-isolation backends shipped as prebuilt binaries | **Yes** | [`metadata/isolation-backends.json`](metadata/isolation-backends.json), enforced by [`scripts/check-backend-license-compliance.sh`](scripts/check-backend-license-compliance.sh) |
| eBPF probe objects (`aa-file-io`, `aa-exec-probes`, `aa-tls-probes`, `aa-syscall-guard`) | **No** | First-party. Built from this repository by `scripts/build-ebpf-probes.sh`, digested into `EBPF_SHA256SUMS` and cosign-signed at release. Not third-party software. |
| Container base images | **No** | Image-layer SBOMs generated by `docker.yml` (`sbom: true`). |

**Known gap, stated plainly:** the cargo dependency graph is *license-gated* by
`deny.toml` but is **not** *notice-enumerated* — this repository does not
currently generate a per-crate attribution list (e.g. via `cargo-about`) for
the `aasm` binary, and no SBOM is produced for the released binaries either.
Only container images have SBOM coverage today. Closing that gap is separate
work and is out of scope for AAASM-5714, which covers the isolation-backend
class of artifact.

## Why the backend class needed its own mechanism

`cargo-deny` evaluates the cargo dependency graph. An isolation backend that
ships as a **prebuilt binary outside that graph** is invisible to it: no
license is checked, no advisory is matched, and nothing fails. That is the hole
`metadata/isolation-backends.json` and its gate close. A backend entering any
distribution channel must appear in that manifest with a reviewed license, or
the build fails.

## Redistributed third-party components

*None at present.*

Agent Assembly does not currently redistribute any third-party prebuilt binary.
The first execution-isolation backend exists (see below) but is not
redistributed on any channel; a backend that *is* bundled gets its notice
section here and the gate begins requiring it.

### Not redistributed: Sandlock (AAASM-5708)

The first execution-isolation backend landed with AAASM-5708 and its measured
provenance is recorded in
[`metadata/isolation-backends.json`](metadata/isolation-backends.json)
(`sandlock` 0.8.6, Apache-2.0, digest verified in CI). **Agent Assembly does
not redistribute it.** It is an external executable the operator installs, so
every channel's strategy is `system` or `not-distributed` — none is `bundled`,
`downloaded` or `source` — and no attribution obligation attaches to anything
this project ships.

This heading is deliberately *not* `### sandlock`. The gate matches a bundled
backend's notice section by exact heading, so if a future change makes any
channel `bundled`, `scripts/check-backend-license-compliance.sh` will fail
until someone writes a real notice section rather than finding this one already
in place.

The gate enforces the other direction too: while a backend's manifest entry is
`status: "pending"`, it must carry **no** provenance fields at all, so an
unmeasured backend cannot acquire a plausible-looking record.

## Adding an entry

When a backend or other third-party artifact starts being redistributed, add a
section here using this template, and add the matching row to
`metadata/isolation-backends.json`. The gate checks that a `bundled` backend's
`id` appears as a heading in this file.

```markdown
### <backend id>

- **Upstream project**: <name and homepage>
- **Version**: <exact released version>
- **Source**: <URL of the exact artifact or source tree>
- **SHA-256**: <checksum of the redistributed artifact>
- **License**: <SPDX identifier>
- **Modifications**: <none | description + link to the patch set>

<verbatim copyright notice and license text, or a path to the bundled license
file, as that license's own terms require>
```

Retaining the upstream copyright notice and license text is an obligation of
every permissive license in the allowlist (Apache-2.0 §4, MIT, the BSD family,
ISC); where the license also requires a statement of changes (Apache-2.0 §4(b)),
the `Modifications` line is where that statement lives, and the manifest's
`modifications.notice_path` must point at the detail.
